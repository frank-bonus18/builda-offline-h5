<h3>audio：BGM / 音效 / 震动</h3>
      <pre><code>await Builda.audio.playBGM("audio/bgm/main.mp3", { loop: true, volume: 0.8 });
await Builda.audio.stopBGM();
await Builda.audio.playSFX("audio/sfx/hit.ogg", { sessionId: "hit", volume: 1 });
await Builda.audio.setMuted(true, "bgm");     // group: "bgm" | "effect"
await Builda.audio.vibrate(2);                // 1 轻 / 2 中 / 3 重</code></pre>
      <ul>
        <li>路径传 assets.zip 内 <code>audio/**</code> 的相对路径；真机由宿主原生（FMOD）播放。</li>
        <li><strong>音频不需要「首次点击解锁」</strong>：真机是宿主原生实现，不受浏览器 autoplay 策略限制，进游戏就能直接播 BGM。不要照搬 Web 游戏惯例做「点击任意处开启声音」的引导层。本地 mock 走浏览器 <code>Audio</code>，可能被 autoplay 拦到首次交互后才出声——这是开发环境现象，不要为它改游戏逻辑。</li>
        <li><strong>不要自己做音乐/音效开关和退出按钮</strong>：平台通用设置/暂停退出页统一提供（含静音开关），游戏设置页里也不要放。</li>
      </ul>

      
<h3>mic：麦克风声控</h3>
      <p>声控玩法（音量/吹气/音高）<strong>优先用官方内置件 <code>BuildaMic</code></strong>（随 SDK 分发，Godot / Unity 同构），
不要直连底层原语：</p>
      <ul>
        <li><strong>Godot</strong>：注册 autoload <code>BuildaMic="*res://addons/builda/mic/builda_mic.gd"</code>；点击回调里 <code>BuildaMic.start()</code>；每帧读 <code>BuildaMic.volume</code>（RMS）/ <code>BuildaMic.pitch</code>（Hz）驱动玩法，监听 <code>state_changed</code> 更新引导 UI。<br><strong>打包注意</strong>：导出后必须把 <code>addons/builda/mic/web/</code> 原样拷进导出目录再压 zip——分析 worker 必须随包分发，本地 dev 有兜底会骗过你，正式包缺文件真机报 <code>WORKER_LOAD_FAILED</code>。</li>
        <li><strong>Unity</strong>：把 <code>BuildaMic</code> 组件挂常驻对象，<code>StartMic()</code> / <code>Volume</code> / <code>Pitch</code> / <code>StateChanged</code>；分析 worker 在 <code>Assets/StreamingAssets/builda-mic/</code>，WebGL 构建自动带上。</li>
        <li>换算法/加特征只改各自的 <code>builda-mic-worker.js</code>（重 DSP 就该在这个 Worker 里跑）；该目录归项目所有，SDK 升级不覆盖。</li>
      </ul>
      <p>直连底层（<code>audio.requestMicrophone</code> + <code>mic.start/read/stop</code>，HTML5 无内置件时用）的核心约束是<strong>两次手势</strong>：</p>
      <ol>
        <li>第 1 次点击（「开启声控」按钮）回调里调 <code>audio.requestMicrophone()</code> 申请权限。<code>available: false</code> = 用户拒绝或无麦：给出明确的阻断提示并允许重试（不能黑屏/卡死/静默）；无麦替代玩法可选、不是必须。</li>
        <li>权限结果回来后<strong>不要直接调 <code>mic.start()</code></strong>——权限回调不在手势上下文（Godot 信号经逐帧轮询派发必然脱离手势），AudioContext 会被自动播放策略拦下且不可恢复。停在「再点一次开始」的引导，<strong>第 2 次点击</strong>回调里调 <code>mic.start()</code>。</li>
        <li>之后每帧 <code>mic.read()</code> 同步拉单声道 float32 PCM（[-1,1]），不用时 <code>mic.stop()</code>。</li>
      </ol>
      <ul>
        <li><code>start()</code> 幂等可重入；并发/重复调用在途去重合并到同一结果，不会返回瞬时 <code>BUSY</code>。</li>
        <li><code>read()</code> 的 <code>dropped &gt; 0</code> 表示拉取过慢被环形缓冲覆盖（实时控制通常无害，别当连续流做录音）；<code>state: "interrupted"</code> 表示采集中断（来电/切后台），SDK 回前台会自动重建，持续中断时引导玩家点击后重调 <code>start()</code>。</li>
        <li>实际采样率以 <code>start()</code> 返回的 <code>sampleRate</code> 为准，期望值不保证生效。</li>
        <li>SDK 只给原始 PCM，不做任何特征分析；音高/音量提取放你自己的 Web Worker，<strong>不要</strong>在 GDScript 或主线程跑重 DSP（会和引擎抢帧预算）。</li>
        <li>开着 BGM 实测声控灵敏度——SDK 显式关闭了回声消除/降噪（否则 BGM 时人声被对消成静音），BGM 串音必然存在于 PCM，阈值要在真实混音下调。</li>
      </ul>
      <blockquote>
        <p><strong>红线：</strong>PCM 只许本地实时分析，禁止录音留存/上传，违反视为审核事故。</p>
      </blockquote>
