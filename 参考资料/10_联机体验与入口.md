<h1>Builda Online</h1>
<p>Builda Online 为 Builda 游戏提供托管联机能力。游戏保留自己的客户端表现和玩法规则，平台负责玩家身份、
匹配、房间调度与联机传输；房间规则由你的 TypeScript 或 Rust Room 源码定义。</p>
<p><strong>复制给 AI</strong></p>
<pre><code class="language-text">请为当前项目接入 Builda Online：读取 https://ai.builda.game/online/setup.md，并严格按照其中的安装与工作流说明执行。
</code></pre>
<h2 id="选择玩家体验">选择玩家体验</h2>
<p>先决定玩家进入游戏、开始一局和结束后的体验。一个游戏可以同时提供多个入口，但每个入口都应属于一种明确模式。</p>
<div class="table-wrap"><table>
<thead>
<tr>
<th>玩家看到的体验</th>
<th>适合场景</th>
<th>联机方式</th>
</tr>
</thead>
<tbody>
<tr>
<td>凑齐固定人数开一局，结束后回大厅重新找人</td>
<td>1v1、多人对战、合作闯关</td>
<td>单局匹配</td>
</tr>
<tr>

<td>CF/CS 风格房间、桌游房</td>
<td>循环房</td>
</tr>
<tr>

</div><p>每种玩法用一个 <code>matchKey</code> 标识，对应 Room 程序、人数、队伍和运行配置。同一玩法可以提供两个独立入口：</p>
<ul>
<li>公共入口：<code>publicMatchmaking=true</code>，由公共 <code>mode</code>（Room、Pool 或 RankPool）决定如何匹配。</li>
<li>私有入口：<code>privateRoomsEnabled=true</code>，直接创建房间，其他玩家凭 Room ID 加入，不参与公共匹配或 Confirm。</li>
</ul>
<p>两种入口可以单独开启、同时开启或同时关闭。私有房没有房主，创建者与成员平权；仍受队伍容量和房间生命周期
约束。公共 Pool/RankPool 对局已确定参与名单，知道 Room ID 也不能新增成员。
AI 会继续确认每个入口的人数、何时允许加入、断线后如何恢复，以及一局结束后玩家去哪里。</p>
<p><strong>排位积分：</strong> 公共 <code>mode</code> 为 RankPool 时，平台按游戏提交的积分配对：入队时传 <code>rankScore</code>（Godot 为
<code>rank_score</code>，Unity 为 <code>MatchJoinOptions.RankScore</code>）。积分必须是 0 到 9007199254740991 的整数。平台只校验数值
范围，不核验积分是否真实；胜负、奖励或排名依赖该积分时，游戏需要自己设计防篡改方案。</p>

</div><p>客户端负责输入、界面和表现；Room 负责校验玩家行为、推进权威状态、广播结果、断线处理和结算。不要把需要
防篡改的胜负、伤害、资源或排名只放在客户端决定。</p>
<h2 id="从接入到上线">从接入到上线</h2>
<ol>
<li><strong>确认项目。</strong> 项目应已接入 Builda，并能识别唯一的客户端引擎。</li>
<li><strong>交给 AI。</strong> 点击页面右上角的“复制给 AI”，把完整接入指令发给项目中的 AI。AI 会安装与项目匹配的 Skill、SDK 和 Mock。</li>
<li><strong>确认方案。</strong> 用玩家语言确认匹配入口、房间人数、房间生命周期、Bot、断线和结算规则。</li>
<li><strong>本地联调。</strong> 用两个不同的本地身份验证加入、状态、消息、断线和离开。</li>
<li><strong>部署 Room。</strong> 只有你明确要求部署或上线时，AI 才会上传 Room 源码并激活线上版本。</li>
<li><strong>真实验证。</strong> 使用两个真实身份验证匹配、进入 Room 和玩法消息，再决定是否公开客户端。</li>
</ol>
<blockquote>
<p>Room 部署可能立即影响相同兼容修订号下新创建的真实房间。纯客户端更新、兼容的 Room 更新和不兼容协议更新
有不同的发布顺序，交给安装后的 Skill 判断，不要用重复上传来试错。</p>
</blockquote>

</div><p>TypeScript / Rust 本地 Mock 可以仿真玩家数据和假订单的 <code>doOrder</code> / <code>fulfill</code>，不上线就能跑通发货闭环；但它不代表
生产存储和真实支付，完整验收仍需在线上完成。</p>
<p>页面地址、<code>localhost</code> 或 <code>127.0.0.1</code> 不能用来判断游戏是否连接本地 Mock。Builda App 也可能从设备本地地址加载
真实游戏 Bundle；客户端只使用安装记录和 Builda 本地开发外壳提供的明确配置。</p>
