<h3 id="iap">iap：内购支付</h3>
      <pre><code>// grantBy 声明预期发货路径；不覆盖订单冻结配置，实际发货按回包 grantBy 分流
const r = await Builda.iap.showPayPanel("coin_pack_1", { grantBy: "client" });
// r.data = { success, orderId, grantBy }   success 只表示付钱成功，订单停在 Paid
// r.data.grantBy === "client"：按 orderId 幂等发货，然后
await Builda.iap.claim(r.data.orderId);
// r.data.grantBy === "room"：把 orderId 交 Room doOrder，客户端不发货不 claim
// { orderId, status: "delivered" }（幂等）
const pending = await Builda.iap.getPendingOrderIds();
// pending.data = { orderIds: string[] }</code></pre>
      <ul>
        <li><code>saleId</code> 即 manifest（<code>builda.publish.json</code>）<code>payPoints</code> 里声明的 <code>payId</code>（格式 <code>^[A-Za-z0-9_-]{1,64}$</code>）。商品配置、订单创建/查询全部由宿主直连平台完成，游戏不要自己拼订单接口。</li>
        <li><code>success == true</code> <strong>只表示付钱成功</strong>，订单停在 Paid，不是发货完成；<code>false</code> 表示取消或失败，不要发货。回包 <code>grantBy</code> 是随这一单冻结的发货方，<strong>以它为准</strong>：<code>client</code> 由客户端按 <code>orderId</code> 幂等发放，<strong>发完必须 <code>claim(orderId)</code></strong>（Paid→Delivered，幂等；不 claim 的单永远留在未交付列表）；<code>room</code> 把 <code>orderId</code> 交给 Room <code>doOrder</code>，<strong>客户端不得发货、不得 claim</strong>。</li>
        <li><code>Builda.pay.showPayPanel</code> 是 <strong>legacy</strong>：宿主在回包前自动 claim，订单直接 Delivered、无法补发、不能用于 <code>grantBy=room</code>。只为线上老游戏保留，新代码不要接；<code>pay</code> 下没有 <code>claim</code> / <code>getPendingOrderIds</code>。</li>
        <li><code>getPendingOrderIds()</code> 只读返回未交付 <code>orderId</code> 列表，<strong>没有</strong> <code>payId</code>/<code>grantBy</code>。发货责任以下单当时冻结的为准，不能用当前价目表反推，也不能从裸 <code>orderId</code> 猜。未知时不要猜成客户端发货。确认是 room 单才把 <code>orderId</code> 交 Room（<code>doOrder</code> 的 <code>allowed</code> 才带可信 <code>payId</code>）；确认是 client 单才客户端幂等发。</li>
        <li><code>payPoints</code> 声明规则：<code>price</code> 是整数，单位平台虚拟币 G 币（1 元人民币 ≈ 10000 G 币），最小 100、建议 100 的整数倍。发货方 <code>grantBy</code> 只允许 <code>client</code> / <code>room</code>；省略或 <code>""</code> 等于 <code>client</code>。Room 发货必须显式 <code>"grantBy":"room"</code>。同一 <code>payId</code> 只能一个发货方。无内购<strong>省略</strong>整个 <code>payPoints</code>（省略 = 不改动平台已有价目表），不要写空数组；当前没有「清空全部付费点」的自助手段，需下架联系平台。</li>
        <li>修改已有 <code>payId</code> 会改变商品映射，改前务必确认。</li>
      </ul>

      
<h3 id="ad">ad：激励视频</h3>
      <pre><code>const r = await Builda.ad.showRewardAd("revive");
// r.data = { success, transId }</code></pre>
      <ul>
        <li><code>posId</code> 是游戏<strong>自定义</strong>的广告位统计标识（如 <code>revive</code>、<code>double_reward</code>），任意字符串，只用于区分游戏内触发点做统计。<strong>不是平台分配的广告位 ID，无需申请、无需在 manifest 声明。</strong></li>
        <li><code>success == true</code> = 有效看完，按游戏自己的设计发放游戏内奖励；<code>false</code> = 失败/中途关闭/宿主未接广告，不发放。<strong>平台只负责播广告并回结果，不发放任何奖励</strong>；<code>transId</code> 是平台广告流水号，可用于游戏自己的展示或服务端校验。游戏不要调用任何广告核销接口。</li>
        <li>浏览器或无宿主时支付/广告返回 <code>HOST_UNAVAILABLE</code>——不能伪造成功。</li>
      </ul>

      
<h3>input：文本输入</h3>
      <p>手机 WebView 里游戏自绘输入框拿不到系统 IME（拼音候选、光标、选区全没有）。起名、输房间号等文本输入一律调：</p>
      <pre><code>const r = await Builda.input.showInputPanel({ placeholder: "输入昵称", defaultValue: "", maxLength: 16 });
// 确认: { confirmed: true, text }   取消: { confirmed: false, text: "" }</code></pre>
      <ul>
        <li>返回的 <code>text</code> 已由平台完成<strong>敏感词审核与长度截断</strong>，拿到直接用，不要再自行送审。</li>
        <li>改名等回填场景把当前值传 <code>defaultValue</code>。<code>maxLength</code> 默认 64、上限 256。</li>
        <li>同刻单例：面板未关时重复调用返回 <code>BUSY</code>。</li>
        <li><strong>不要</strong>自绘文本框监听键盘事件。</li>
      </ul>

      
<h3>rank：排行榜</h3>
      <p>榜单必须先在 <code>builda.publish.json</code> 的 <code>rankBoards</code> 声明并随发布审核生效
（每榜 <code>rankId/displayName/sortType/cycleType/minScore/maxScore</code>，最多 100 个榜；
<code>sortType: asc|desc</code>，<code>cycleType: day|week|month|forever</code>）。</p>
      <pre><code>await Builda.rank.submitScore("weekly_score", 1234);
const r = await Builda.rank.getRankList("weekly_score", { limit: 50 });
// r.data = { rankId, list: [{rank, score, player}], self: {rank, score} | null }</code></pre>
      <ul>
        <li>分数是整数，平台总范围 ±9999999999；每榜自己的 min/max 由宿主按已发布配置权威校验（未发布 <code>RANK_NOT_FOUND</code>、越界 <code>SCORE_OUT_OF_RANGE</code>）。</li>
        <li>宿主按 <code>sortType</code> 保留每玩家每周期最优成绩——结算时直接提交即可，不用自己比大小。</li>
        <li><code>getRankList</code> 默认 50、上限 100；<code>self</code> 为 <code>null</code> 表示本周期未上榜。</li>
        <li><strong>改 <code>rankId</code> 等价于换新榜</strong>（历史分丢失）；改排序/周期/分数范围或删榜会在审核发布后清分。</li>
        <li>mock 版<strong>不校验榜单配置</strong>（拿不到 manifest），只回固定假对手供 UI 调试；真实语义要在 Builda App 草稿试玩里验证。</li>
      </ul>
