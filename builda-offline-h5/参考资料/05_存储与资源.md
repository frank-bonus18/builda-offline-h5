<h3>privateKV：玩家云存档</h3>
      <p>当前游戏 × 当前玩家的私域存档，value 是<strong>不透明字节流</strong>（JS 侧 <code>Uint8Array</code>，Godot 侧
<code>PackedByteArray</code> + <code>var_to_bytes()</code>，Unity 侧 <code>byte[]</code>）。接口：
<code>get / set / remove / getMany / setMany / removeMany</code>。</p>
      <div class="table-wrap"><table>
        <thead><tr><th>项</th><th>规则</th></tr></thead>
        <tbody>
          <tr><td>key 格式</td><td><code>^[A-Za-z0-9_:-]{1,64}$</code>（新代码建议只用字母、数字、<code>_</code>、<code>-</code>）</td></tr>
          <tr><td>单 value</td><td>≤ 32KB（按解码后字节数）</td></tr>
          <tr><td>批量</td><td>≤ 32 key / 次（SDK 不自动拆批，超过直接返回 <code>BATCH_TOO_LARGE</code>）</td></tr>
          <tr><td>总配额</td><td>每玩家每游戏总活 key ≤ 100（无聚合字节配额）</td></tr>
          <tr><td>写频率</td><td>服务端管控约 60 次/分钟，batch 算 1 次（mock 不模拟）</td></tr>
          <tr><td>并发</td><td>last write wins，无版本号/CAS</td></tr>
          <tr><td><code>get</code> 返回 <code>null</code></td><td>key 不存在（空字节是合法值，删除必须显式 remove）</td></tr>
          <tr><td><code>setMany</code></td><td>整批校验，任一违规<strong>整批拒绝</strong>；写入尽力、不承诺事务</td></tr>
          <tr><td><code>removeMany</code></td><td>对不存在的 key 幂等</td></tr>
        </tbody>
      </table></div>
      <h4>使用规范</h4>
      <ul>
        <li><strong>游戏自行维护的私域字节存档走 privateKV</strong>——不要自建 localStorage、IndexedDB、Cookie 或引擎本地文件存档。只有 privateKV 的数据能被平台统一管理（玩家在 App 里重置存档）；绕开自存的数据平台管不到，重置后会出现数据残留。</li>
        <li>按事件节点写入（过关、结算、购买完成），多 key 一起变时用 <code>setMany</code> 合并成一次写。<strong>不要</strong>每帧/定时写，不要当实时状态同步用——高频写会被真机拒绝。</li>
        <li>启动时读多个 key 用 <code>getMany</code> 一次取回，不要逐 key 串行 <code>get</code>；超过 32 key 需自行显式分批并逐批检查结果。</li>
        <li>校验分层：key 格式、单值 32KB、批量 32 key 由 SDK 前置校验；总活 key 100 与写频率由服务端权威执行。超限返回明确错误码（<code>VALUE_TOO_LARGE</code> / <code>QUOTA_EXCEEDED</code> 等），不会静默截断；mock 版配额与真机一致，本地就能撞到并修复。</li>
      </ul>

      
<h3>assets：平台资源包</h3>
      <p>大体积资源（音频、3D 模型等）不打进游戏主包，单独打成 <code>assets.zip</code> 经
<code>builda assets upload</code> 上传，内部两个顶层子树：</p>
      <ul>
        <li><code>audio/**</code>：宿主音频通道播放（<code>.mp3</code> / <code>.ogg</code> / <code>.wav</code>），配合 <code>Builda.audio.*</code> 使用。</li>
        <li><code>res/**</code>：游戏代码<strong>自己 fetch</strong> 的大资源（3D 模型、纹理、关卡数据、AssetBundle、data-only pck 等）。</li>
      </ul>
      <p>限额：单文件 ≤ 32MB、解压总量 ≤ 320MB、文件数 ≤ 10000；禁止脚本/可执行内容
（<code>.js</code> / <code>.wasm</code> / <code>.html</code>）与字体。</p>
      <ul>
        <li><strong>禁止写死 CDN URL</strong>——<code>assetsBaseUrl</code> 每次重传都会变。永远用相对路径现取：<code>Builda.assets.url("res/models/car.glb")</code>（Godot <code>asset_url(...)</code>，Unity <code>BuildaSDK.AssetsUrl(...)</code>），返回值总是绝对 URL。</li>
        <li>已走 <code>res/**</code> 的资源不要再打进主包 zip（体积白付两遍）；主包仍须自包含到「可进入并开始核心玩法」，<code>res/**</code> 只做延迟加载内容。</li>
        <li>加载失败必须可感知、可重试（进度条/占位/重试按钮），不允许白屏或卡死。</li>
        <li>本地开发把 <code>audio/</code>、<code>res/</code> 拷进构建目录即可闭环：mock 版在无 assetsBaseUrl 时按页面所在目录解析成绝对 URL，Godot <code>HTTPRequest</code> / Unity <code>UnityWebRequest</code> 可直接用；正式包里删掉这些本地拷贝。</li>
      </ul>
