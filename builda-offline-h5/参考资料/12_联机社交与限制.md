<h2 id="builda-app-自带的聊天与邀请">Builda App 自带的聊天与邀请</h2>
<p>联机房间里的聊天和邀请好友不需要你自己做服务器或界面，Builda App 已经提供，SDK 负责在正确的时机把游戏
和它们接起来。</p>
<h3 id="房间聊天">房间聊天</h3>
<ul>
<li>Builda App 为每个 Room 提供一个聊天群，群就是这个 Room，成员进房后即可在 App 的聊天界面里发言。</li>
<li>游戏在拿到 Room 之后让 SDK 入群，同时告诉 App 玩家属于哪个队伍（<code>team_id</code> 由游戏自己定义）；
主动离房、Room 关闭、断线重连超时或关闭连接时，SDK 自动退群，游戏不用处理。</li>
<li>聊天内容的发送、展示和审核都在 Builda App 里完成。App 推送的群消息也会送到游戏，游戏可以用它做头顶
气泡或战斗记录，但不能通过 Online 发送消息。</li>
<li>当前环境没有聊天能力时（本地 Mock、浏览器直接打开、旧版 Builda App），SDK 返回不可用，游戏应隐藏聊天
入口，不要重试或自建替代。</li>
</ul>
<h3 id="房间邀请与加入">房间邀请与加入</h3>
<ul>
<li>玩家进入任何 Room 后，SDK 会自动告知 Builda App 当前所在的房间，App 据此显示联机成员入口并提供邀请好友
的功能。发出邀请由 Builda App 承担，Online 不提供发送邀请的接口。</li>
<li>被邀请的玩家在 Builda App 里点击邀请，App 会拉起游戏并把邀请带给它。游戏在启动流程中一次性读取邀请，
取得 Room ID 后按 ID 加入；没有邀请时走正常大厅流程。</li>
<li>邀请只是提示，能否进房仍由平台判定：房间已满、已关闭，或公共 Pool/RankPool 对局已经确定名单时，
按稳定错误码提示玩家。</li>
<li>游戏也可以用自己的社交系统分享 Room ID，其他玩家凭 Room ID 加入，效果与 App 邀请一致。</li>
</ul>
<p>聊天和邀请对公开房与私有房完全一样。AI 接入时会按你的玩法决定聊天入口放在哪里、<code>team_id</code> 如何划分，
以及启动时如何处理邀请。</p>

<h2 id="常见问题">常见问题</h2>
<h3 id="需要自己学习全部-api-吗">需要自己学习全部 API 吗？</h3>
<p>不需要。先确认玩家体验和规则，把安装入口交给项目 AI。AI 应根据当前引擎和 Room 语言只读取相关公开资料，
完成客户端、Room、配置和本地验证的闭环。</p>
<h3 id="本地测试通过就能上线吗">本地测试通过就能上线吗？</h3>
<p>不能。本地 Mock 适合验证业务规则，但不模拟真实鉴权、匹配算法、WebRTC/TURN、容量或安全隔离。上线前仍需用
真实身份创建新 Ticket 和 Room 验证当前线上 Artifact。</p>
<h3 id="可以同时使用-typescript-和-rust-room-吗">可以同时使用 TypeScript 和 Rust Room 吗？</h3>
<p>一个项目应选择一种 Room 语言。已有源码时沿用项目证据；新项目无法判断时，由作者选择。客户端引擎和 Room
语言彼此独立，例如 Unity 客户端可以配 TypeScript Room。</p>
<h3 id="聊天和邀请好友需要自己开发吗">聊天和邀请好友需要自己开发吗？</h3>
<p>不需要。房间聊天群和房间邀请由 Builda App 提供。游戏在进房后调用一次入群（全房间聊天 <code>team_id</code> 传 0），退群由
SDK 自动完成；再在启动时处理一次邀请。AI 接入联机时默认接入聊天，不需要可以告诉它。本地 Mock 不模拟这两项，需要在 Builda App 里用真实身份验证。</p>
<h3 id="如何查看线上-room-问题">如何查看线上 Room 问题？</h3>
<p>安装包包含独立的日志诊断 Skill。让项目 AI 查询 Room 日志、丢弃统计或退出原因时，它会使用只读诊断流程，
并避免输出玩家隐私、凭据或完整敏感负载。</p>
<p>同游戏房内、异房或离线玩家的数据可由 Room 异步单键读取与条件更新；旧房内缓存和支付接口保留。目标无需加入当前房间。</p>
